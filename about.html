About ShopNow Kitchen: a publication, with its workings visible

We compare countertop appliances on checkable specs and human buyer questions. Here is who writes, how we check, what “published” means here, and what we refuse to claim.

By the ShopNow Kitchen Desk · Updated 2026-11-20

Authorship

Every page is bylined the ShopNow Kitchen Desk — an editorial desk, not a person. We do not invent a name, credentials, a test kitchen, or hands-on experience. If we ever test something, the page will say what was tested, when, and what was observed. Until then we compare manufacturer and listing specs and say exactly that.

This is a decision, not a gap. A named expert byline would help readers and search engines judge us — but only if it is real. See Q-06 and SG-09: supply one human name and bio and the site will use it; otherwise the desk byline stays and so does the “no testing claimed” rule.

Methodology

  1. Start from the submitted link; record intent and observation in separate fields, never merged.
  2. Read the official source for every claim: the listing for a spec, the regulator for a safety figure, the programme agreement for a rule.
  3. If a value cannot be confirmed, the cell stays blank and the item is flagged. Nothing is inferred, averaged or “best guessed”.
  4. Every page passes a compliance gate before publish (scripts/check_site.py): disclosure present, paid links qualified, no static prices, no broken internal links, sitemap coverage complete.
  5. Measure with the five defined events; fill the campaign ledger only from first-party reports, with a date attached.

Brand, seasons, and clusters

  • Brand: ShopNow Kitchen — warm paper, ink text, terracotta and sage. Typography and whitespace, not badges and countdown timers.
  • Imagery: commissioned editorial illustrations, always captioned as illustrations. No Amazon product images and no logos — the IP licence restricts them, and a scraped photo would promise a product we have not seen.
  • Seasons: currently “Holiday cooking” alongside everyday cooking; grilling and holiday-baking angles run as guides, not as banners that expire on the server.
  • Clusters (computed from data, so this cannot drift): Air Fryers (3 products, 11 guides); Meat Thermometers (2 products, 4 guides).

How a reader makes the decision

Every category page opens with reader situations — “two of you, most weeknights” — and answers them by naming the one listed spec that settles the case, with the listing linked. No profile ranks a product best, and no profile reaches past a listed specification. Product pages add what the listing says, where the listing contradicts itself, and the questions readers actually ask, each with its source.

Publishing cadence

A new guide is one JSON file in data/guides/, then npm run build. Sitemap, RSS, the search index, this page’s cluster counts and every nav rail pick it up from the same source — no hand-edited lists. The next topic should come from measured queries rather than instinct, which is why measurement is wired even while it records nothing yet. Every planned topic and how it was chosen is published on the topics page, so the editorial pipeline is visible rather than implied.

Corrections

If a row on this site is wrong, that is a defect, not a difference of opinion. Flagged items are published on Flagged for review with the source link and the action that would settle them; we would rather show an open question than fill it with a guess.
