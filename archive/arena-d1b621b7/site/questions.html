Before You Decide

A decision is only as good as the facts behind it. Fourteen questions — each with what we know (sourced), what's missing, and how the gap gets closed. Nothing here is guessed; if the answer isn't known, the cell says so.

Q-01 · Are the five submitted codes valid ASINs?

Answer (what we know)
Not confirmed — and the evidence points to no. All five codes are exactly 9 characters with lowercase letters; Amazon Ads states an ASIN is "always 10 characters long" and starts with "B" or is numeric (V-12). Fetches of amazon.com/dp/<code> failed for all five on 2026-11-20 while two known-good controls succeeded (FLG-001).
Source
Amazon Ads: targeting guide (ASIN = 10 characters) · observation log O-06/O-07
Missing information
Whether the codes are truncated/obfuscated forms of real ASINs, or identifiers from a different system entirely.
How we discover it
Open each submitted link in a logged-out browser, note the final /dp/ code, and compare with the code in the link path; ask the link provider for their mapping table.
Decision it blocks
Which product each register row refers to (SG-06, product copy, any future price display).

Q-02 · What do the supplied links actually promote?

Answer (what we know)
Observed and recorded — and they don't match the intended codes. All five resolved to real Amazon listings: three air fryers (B0CDY277D3, B09B7SB46R, B08DKYBTPH) and two meat thermometers (B0DHZTCNR5, B0DZFD6R9Z) on 2026-11-20 (FLG-002).
Source
product-intent record (intended vs observed blocks)
Missing information
Which side is authoritative: the code in the link path, or the listing it lands on.
How we discover it
Owner confirms intent per row; re-run the redirect check monthly to catch link reuse.
Decision it blocks
Product names on the shortlist, guide-to-product matching, catalog expansion.

Q-03 · Is link.amazon an official Amazon domain?

Answer (what we know)
Partially: it resolves in DNS to AWS CloudFront addresses (18.172.170.x) and redirects into amazon.com product pages with Amazon-style parameters (FLG-008). Domain ownership (WHOIS/registrar) has not been independently verified.
Source
observation O-08 · Amazon Program Policies (link clarity rules, V-08)
Missing information
Registrar record / WHOIS for link.amazon.
How we discover it
One manual WHOIS lookup or ICANN Lookup by the owner; result logged here.
Decision it blocks
SG-06 (whether these links qualify as Special Links at all).

Q-04 · Is the tracking ID shopnow047c-20 active on the Associates account?

Answer (what we know)
Unverified. The format is compatible with Amazon's documented tag pattern (XXXXX-##, V-03), but validity is only observable inside Associates Central (FLG-004).
Source
Associates Program Policies §2(b)
Missing information
Account status, tag assignment, and whether this tag is the one on the supplied links.
How we discover it
Owner signs in → Account Settings → check tracking IDs; click one test link and inspect the tag= parameter in the destination URL.
Decision it blocks
SG-19 (one-link test), any revenue reporting.

Q-06 · Do the supplied links qualify as "Special Links"?

Answer (what we know)
Unresolved — and we do not claim they're invalid. Amazon requires tagged formats (V-02) and prohibits shortening that obscures the Amazon destination (V-08); whether these links carry a proper tag internally can't be seen from outside (FLG-003).
Source
Operating Agreement §1 · Program Policies §6(w)
Missing information
Destination URL parameters after full redirect chain (tag parameter), and the Associates-side report for a test click.
How we discover it
SG-19: click one link per product inside the enrolled workflow; confirm destination + that the click appears in the tracking report.
Decision it blocks
SG-06 link replacement, revenue attribution trust.

How we discover it

Q-11 · Which marketplace's rules apply?

Answer (what we know)
The tag suffix -20 and all observed listings are amazon.com (US) — so US Associates terms and FTC guidance were used as the compliance baseline (V-01, V-10). The Amazon Associates agreement set is per-marketplace, so this should be confirmed.
Source
US Operating Agreement · 16 CFR Part 255
Missing information
Confirmatory note from the account owner: US program enrolled, not another region.
How we discover it
One line from the owner; if non-US, the compliance page gets re-based on the correct marketplace agreement.
Decision it blocks
