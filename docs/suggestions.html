Suggestions

The decision queue. Every item states what it is, why it matters, and the paths you can choose between — nothing marked needs decision gets implemented without a pick. Items marked done were part of the initial build and are listed so the full picture is reviewable in one place.

SG-01

Lead with the products, not the verification process

done

The landing page is a publication front page: buyer question → guides → shortlist. Every dashboard surface (register, flags, ledger, measurement) is one click away in the footer's Dashboard group, reachable but never in the buyer's face.

Path A (chosen): publication front page, dashboards in footerPath B: dashboard-style home — rejected, reads like an audit
Effort: shippedImpact: buyer trust + conversion pathsee front page
SG-02

Single navigation group; dashboard surfaces in footer

done

One reader-facing nav (Home · Guides · The Shortlist · Suggestions · Before You Decide · Summary). Operational pages live under the footer's Dashboard heading so the information architecture stays one-level deep.

Path A (chosen): two-tier — reader nav + footer dashboardPath B: mega-menu mixing both — rejected, noise
Effort: shippedRelated: SG-27
SG-03

Disclosure strip above the fold on every page, repeated in footer

done

The Associates statement sits in an amber strip directly under the masthead — before any content, on every page including this one — and again in the footer. Placement follows FTC's "unavoidable" standard (V-10) and Amazon's required wording (V-01). A CI check fails the build if it's ever missing.

Path A (chosen): static strip in HTML (works without JS)Path B: JS-injected banner — rejected, breaks no-JS and crawlers
Enforced by: scripts/check_site.py
SG-04

Every outbound product link marked as sponsored

done

All product links carry rel="sponsored nofollow noopener" plus a js-outbound hook for click measurement. The build checker fails if any link.amazon or /dp/ link appears without sponsored.

Path A (chosen): rel=sponsored + checker gate
Enforced by: scripts/check_site.py
SG-05

Product-intent confirmation record with separated fields

done

Each submitted link stores: intended code, official listing URL, confirmation date, source — in the intended block. Observed redirect target, title and check date live in a separate observed block. The two are never merged; all five mismatches are flagged.

Path A (chosen): two-block JSON + rendered tables
products.json · rendered record

Amazon requires links to properly use its "tagged" formats (V-02) and warns that unclear link shortening is prohibited (V-08). The supplied short links' exact compliance status is unresolved (FLG-003) — we do not claim they are invalid. Nothing gets swapped until the one-link test below runs.

Path A: owner runs one-link-per-product test in the enrolled Associates workflow, records destination + tracking report, then swap — recommended Path B: keep submitted links (marked sponsored) until a later batch test Path C: swap to /dp/+tag links now — rejected, untested against the Associates account
Effort: 1 session (A) · Blocks: revenue attribution confidenceQ-06

SG-08

Set a publishing cadence and hold to it

proposed

Recommended: one guide per fortnight, published Tuesday, added to sitemap and feed the same day. Cadence beats bursts for how search engines treat a new site — but it's an ongoing commitment, so it needs an owner pick.

Path A: 1 guide / fortnight — recommendedPath B: 1 guide / month, lower loadPath C: burst of 4/quarter, then pause
Effort: 2–4 h per guide · Blocks: SG-20 topic loop

SG-11

Privacy-preserving outbound-click counter

done

No cookies, no third-party requests, random per-browser session id, referrer truncated, ring buffer capped at 500 events. Documented on the privacy page.

Path A (chosen): first-party, cookieless, sendBeaconPath B: third-party analytics — rejected, conflicts with privacy positioning
Code: docs/assets/analytics.js
SG-12

Deploy the self-hosted analytics endpoint

needs decision

Endpoint code is shipped (analytics/endpoint.js for Cloudflare Workers, analytics/server.py for any Python host) but not deployed — hosting requires credentials this session doesn't have (FLG-006). Until then the site runs in local mode and the Measurement page shows this browser's events.

Path A: Cloudflare Worker + KV (free tier, ~15 min) — recommended Path B: small VPS running server.py Path C: stay local-only — no cross-device data, weakens SG-10
Effort: A/B 1 session · Blocks: real click analytics, SG-24Q-07
SG-13

Approve the five-event taxonomy

proposed

The brief referenced "the five defined events" but no definition existed in the repo. We proposed: page_view, outbound_product_click, guide_cta_click, search_query, subscribe_click — deliberately excluding conversions, which only enter via authorized Associates reports (FLG-009).

Path A: approve as proposed — recommendedPath B: revise list (send the replacement five)
Blocks: event dashboards, ledger alignment

Path A (chosen): empty ledger + entry rules
