SG-01 Get five real listing URLs before marketing anything

  
The product identity is the only input the whole site is missing, and it is a two-minute job on a logged-in machine.

  
WhyEvery token in the brief is 9 characters (SRC-12), which cannot be resolved from here; the register therefore publishes blanks. Until an ASIN is confirmed, no title, price or suitability claim can be written without inventing it.

  

    
  

  
RecommendedB, then A for the record. It converts a data-cleanup task into the compliance step the brief already asked for.

  
Effort S · Impact blocking · Depends on Q-01, Q-02

  
Hand this to a build session

    
For each of the five confirmed listing URLs, set intended_asin, official_listing_url, confirmed_on and confirmation_source in data/product-intent.json, keep observed_redirect_target separate, then rebuild so the Picks table fills its title column from the listing page only.

    

  
Status: pending review · chosen option: none





  
SG-02 Replace every outbound href with the tagged Special Link we generate

  
The site should never hand a reader a shortened or host-ambiguous URL.

  
WhyThe Operating Agreement permits only the tagged formats Amazon provides (SRC-01 §1); a malformed link simply does not accrue (SRC-02 §2(g)); and shortening that obscures the destination is separately prohibited (SRC-02 §6(w)). The supplied link.amazon form shows no tag parameter to us, which is a question to resolve, not an accusation (FLG-003).

  

    
  

  
RecommendedA for every product row; C only for guides that need a category-level exit and already carry original analysis.

  
Effort S · Impact high · Depends on Q-03

  
Hand this to a build session

    
Point the generator's link builder at data/product-intent.json only, emitting https://www.amazon.com/dp/<confirmed-asin>?tag=<tracking-id> with rel="sponsored nofollow" and a (paid link) label, and fail the build if any outbound href lacks tag=.

    

  
Status: pending review · chosen option: none





  
SG-03 Pick the marketplace the reader actually buys on

  
A Dutch reader sent to amazon.com converts worse and returns more; the tag locale has to match the store.

  
WhyLinks must point at an Amazon Site covered by the associate's locale (SRC-01 §1); the operator sits in Naaldwijk, NL, while the supplied ID looks like the US program. We cannot see which locales the account is enrolled in.

  

    
  

  
RecommendedAnswer Q-03 first; if the account is US-only, ship A now and add the language layer in C later. Do not fake locale routing with a redirect - that is a Redirecting Link (SRC-02 §2(e)).

  
Effort M · Impact high · Depends on Q-03

  
Hand this to a build session

    
Add a marketplace table to site.config.json (store host, Associates host, locale tag) and make the link builder take its host and tag from that table; ship a visible, manual store switch that rewrites hrefs client-side without redirecting anyone.

    

  
Status: pending review · chosen option: none





  
SG-04 Turn each product row into a decision card, not a verdict

  
Buyers act on trade-offs they can check; they bounce on superlatives they cannot.

  
WhyThe Program Policies forbid inaccurate, overbroad or misleading product claims (SRC-02 §2(b)), and Google's own self-check asks whether a heading exaggerates (SRC-08). A 'what to check / who it suits / what we have not confirmed' card satisfies both and reads like a shop.

  

    
  

  
RecommendedA now, C on the two cluster guides. Add B only after a real test exists.

  
Effort M · Impact high · Depends on Q-01

  
Hand this to a build session

    
Extend the product card component with 'suited for', 'check on the listing' and 'not yet confirmed' blocks driven by content/product-cards.json, and remove any scoring UI until a test record exists.

    

  
Status: pending review · chosen option: none





  
SG-05 Handle price and commission the only two legal ways

  
Either the store serves the number, or the API does - never the article body.

  
WhyPrices and availability may be shown only in an Amazon-served link or from Creators/PA API under the License (SRC-02 §2(b)); Creators API needs 10 qualifying sales in 30 days (SRC-05) and PA-API 5 already returns 403 (SRC-06). Comparison displays additionally require the lowest new (and supplied used) price.

  

    
  

  
RecommendedA today; apply for B where the account allows; queue C as the unlock event that justifies building comparison logic.

  
Effort S · Impact high · Depends on Q-05, Q-06

  
Hand this to a build session

    
Keep all price fields blank in data, render the 'price shown on the listing' microcopy in the product card, and keep gate G-06 armed so any currency pattern without a provenance key fails the build.

    

  
Status: pending review · chosen option: none





  
SG-06 Switch on measurement in the order the host allows

  
Local counting now, a collector only when a server and a legal basis exist, Search Console regardless.

  
WhyPages is static (SRC-09), so a self-hosted endpoint cannot live here; sub-tags may never be tied to an end user (SRC-02 §2(b)); synthetic traffic is banned (§6(s)); and GitHub already logs IPs, so the privacy text must be accurate. The brief's five events are not enumerated in what we received (Q-12).

  

    
  

  
RecommendedA + C now, B as the opt-in upgrade. Do not deploy a hosted analytics tag on an EU-audience site without Q-11 answered.

  
Effort S · Impact high · Depends on Q-11, Q-12

  
Hand this to a build session

    
Keep assets/js/clicks.js in local-only mode, ship tools/collector.sample.mjs behind an explicit opt-in, and add a footer 'measurement' line generated from the state of endpoint in site.config.json.

    

  
Status: pending review · chosen option: none





  
SG-07 Automate the schedule, not the scraping

  
A weekly job that opens the re-verification queue, not a robot that visits Amazon.

  
WhyProgram Content that is gone from Amazon must be removed promptly (SRC-02 §6(c)), which is a real recurring duty; but artificially generating clicks or sessions, by robot or software, is prohibited (§6(s)). So the automatable part is staleness detection on our own data, and the human part is the check.

  

    
  

  
RecommendedA. It keeps the compliance duty visible and refuses the automated-traffic line by design.

  
Effort S · Impact medium · Depends on Q-05

  
Hand this to a build session

    
Add tools/freshness.mjs that lists rows older than 30 days and a weekly workflow calling it; fail the build when a product row is stale and unreviewed.

    

  
Status: pending review · chosen option: none





  
SG-08 Publish the four briefed questions as guides, then let queries pick the fifth

  
One question per page, one page per week, next topic chosen from measured impressions.

  
WhyThe brief supplies four working titles and no demand evidence (Q-07). Google's guidance rewards pages that answer a specific question with original analysis and headings that do not exaggerate (SRC-08), and Search Console is the free first-party source for what to write next.

  

    
  

  
RecommendedA now, C at eight guides, with a hard rule that no page publishes while carrying an unverified product claim.

  
Effort M · Impact high · Depends on Q-07, Q-10

  
Hand this to a build session

    
Add a guide to content/guides/, run the generator, and confirm the new URL lands in sitemap.xml and feed.xml automatically; keep titles question-shaped and free of superlatives.

    

  
Status: pending review · chosen option: none





  
SG-09 Give search one site to index, and keep the feed link-free

  
Sitemap, canonical, one H1, JSON-LD, and an RSS feed that carries headlines - not store links.

  
WhyStructured data fields and their meaning are documented (SRC-07); the site lives on a sub-path so canonical must be absolute and internal links relative (SRC-09); and a feed body containing store links is where syndication puts affiliate links in someone else's mailer, which the Participation Requirements restrict to solicited messages (SRC-02 §4).

  

    
  

  
RecommendedA, and add a Search Console submission step to the deployment checklist rather than a new feed.

  
Effort S · Impact medium · Depends on nothing

  
Hand this to a build session

    
Keep G-13 armed (assert no store host appears inside feed item bodies) and record the Search Console submission date in data/sources.json as an operator-supplied note.

    

  
Status: pending review · chosen option: none





  
SG-10 Decide the domain before earning any ranking

  
github.io/WinC is fine to prove a thesis and bad to compound one.

  
WhyProject Pages sites sit under /WinC/ (SRC-09), a name that says nothing to a buyer and re-roots every canonical, sitemap and feed when changed. The chosen name must also avoid Amazon marks and misspellings (SRC-02 §1(g)).

  

    
  

  
RecommendedA until the first ten guides exist, then B; flip base_url and rebuild in the same commit.

  
Effort S · Impact medium · Depends on Q-08

  
Hand this to a build session

    
Change site.config.json base_url and path_prefix, add the CNAME file at the repo root, rebuild, and re-run the link gate to prove no absolute /WinC/ link survived.

    

  
Status: pending review · chosen option: none





  
SG-11 Do not build the price-alert feature the plan implies

  
Drop-alerts are the most-requested affiliate widget Amazon expressly forbids.

  
Why'Unless otherwise agreed by Amazon, your Site must not have price tracking and/or price alerting functionality' (SRC-02 §6(y)). A 'notify me when under €X' form looks like an obvious conversion win and is a contractual breach.

  

    
  

  
RecommendedA. Keep C as a recorded question so nobody re-litigates it.

  
Effort S · Impact high · Depends on nothing

  
Hand this to a build session

    
Leave the alert feature unbuilt, keep gate G-08 asserting its absence, and record the option-C question in data/questions.json as Q-11a if the operator wants the written ask pursued.

    

  
Status: pending review · chosen option: none





  
SG-12 Buy trust with a name, a review log and a corrections line

  
A publication has someone to call out; a content farm does not.

  
WhyGoogle's self-assessment asks who created the content and how (SRC-08); the Endorsement Guides care that endorsements reflect honest opinion (SRC-04); and §5 fixes first-person disclosure wording (SRC-01). None of that survives an unnamed desk forever.

  

    
  

  
RecommendedB now, A as soon as the operator names a person; never C.

  
Effort S · Impact medium · Depends on Q-09

  
Hand this to a build session

    
Set authorship.person_byline, add reviewed_on to each guide, and render a Corrections block from data/corrections.json (create it, empty, with a documented schema).

    

  
Status: pending review · chosen option: none





  
SG-13 Illustrate with our own art, labelled as illustration

  
Own imagery lifts the page and stays clear of product-content rights.

  
WhyProgram Content may only be resized or truncated without altering meaning, and must vanish when Amazon removes it (SRC-02 §6(a),(c)); the IP License terms were not reachable from here (Q-13). Generating our own diagrams sidesteps an unresolved question and gives the site a look.

  

    
  

  
RecommendedA; revisit B only with the IP License open in front of us.

  
Effort S · Impact medium · Depends on Q-13

  
Hand this to a build session

    
Keep assets/img limited to original illustrations, each with a caption node saying 'illustration, not product imagery', and have the gate reject img elements without alt.

    

  
Status: pending review · chosen option: none





  
SG-14 Write the three policy pages once and link them everywhere

  
Disclosure, privacy, and how-we-verify - short, plain, and in the footer of every page.

  
Why§3(e) of the Participation Requirements expects disclosure of cookies and pixels; GitHub Pages logs IP addresses (SRC-09); Amazon names GDPR and the ePrivacy Directive as applicable law; and the FTC standard is that the connection is disclosed where the recommendation is read (SRC-04).

  

    
  

  
RecommendedA, with the disclosure page carrying the exact §5 sentence and the quote of where it comes from.

  
Effort S · Impact medium · Depends on Q-14

  
Hand this to a build session

    
Keep /disclosure/, /privacy/ and /how-we-verify/ generated from site.config.json so any change to measurement state rewrites the privacy wording automatically.

    

  
Status: pending review · chosen option: none





  
SG-15 Adopt one primary metric and refuse the rest

  
'Clicks that reached a listing we can confirm' is the only number this site can currently earn honestly.

  
WhyRevenue depends on rates we have not verified (Q-06), attribution is 24 hours with an 89-day cart tail (SRC-02 CIS §1), and reported orders arrive only from the account's own reports. Optimising a derived number before the inputs exist produces confident nonsense.

  

    
  

  
RecommendedA as the operational metric, C as the editorial signal, ledger stays empty until first authorized report.

  
Effort S · Impact high · Depends on Q-10, Q-15

  
Hand this to a build session

    
Render the ledger from data/ledger.csv with an 'authorized source' column required per row, and have the gate reject any ledger row whose source is not a first-party report.

    

  
Status: pending review · chosen option: none
